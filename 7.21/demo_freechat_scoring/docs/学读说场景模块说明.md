# UniSpeaking Demo 学 · 读 · 说场景模块

## 1. 当前流程

用户可以保留原有“直接对话”，也可以选择“场景对话”：

```text
生成场景内容 → 学习并播放单词/短语/句子 → 句子跟读评分 → 场景自由对话 → 分模块报告
```

新增功能作为现有对话链路的外层流程，不改变原有实时语音、逐轮评分和会话报告接口。

## 2. 学

后端根据场景和学习者等级调用百炼 `qwen-plus`，结构化生成：

- 6 个场景单词
- 4 个实用短语
- 4 个完整句子

所有内容都可以通过浏览器独立语音合成播放。播放不会启动实时对话、触发 VAD 或写入对话上下文。系统记录本次页面中已播放的内容数量。

## 3. 读

只有完整句子提供跟读按钮。浏览器录制 16 kHz 单声道 WAV，后端从 `sentence_id` 获取固定目标句子，并将“目标句子 + 用户音频”提交给讯飞 ISE。

跟读不经过 ASR 纠错，也不做语法和语言质量评分。结果包括发音表现、准确度、流利度、完整度及逐词反馈；同一句可以多次尝试，报告取该句最佳成绩。

## 4. 说

进入“说”阶段后继续使用现有链路：百炼实时语音对话、PCM 评分流、受限 ASR 纠错、讯飞发音评分、百炼语言质量评分和任务完成度评分。

场景目标、短语和核心句子会作为会话练习目标提供给 AI，但不会强迫用户照读。原有“说”模块总分公式保持不变。

## 5. 报告与兼容性

场景模式的最终报告增加：

- 学：已播放内容数 / 总内容数
- 读：各句最佳成绩的平均发音表现
- 说：原有发音表现、语言质量、任务完成度和综合分

“学”和“读”不会混入“说”的综合分。场景生成或跟读失败时，用户仍可进入现有对话模块；选择“直接对话”时，页面和接口行为与原 Demo 一致。

当前场景、播放进度及跟读记录为 Demo 级内存数据，页面刷新或服务重启后不会长期保留。
