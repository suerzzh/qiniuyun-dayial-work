# 场景训练每日推荐滚动修复设计

日期：2026-07-16

## 问题

正式站点的 `#/scenes` 页面在较矮桌面视口中无法向下滚动到“每日推荐”的第三张场景卡。

线上 1280×720 视口的测量结果：

- `.scene-page` 的 `clientHeight` 为 658px，`scrollHeight` 为 917px；
- `.scene-page` 的最终计算样式是 `overflow: hidden`；
- 每日推荐列表顶部为 759px，已位于可视区域之外；
- 第三张卡片位于 963—1053px；
- 推荐列表自身还被限制为 `max-height: 200px` 并启用第二层内部滚动。

因此数据和 DOM 都正常，根因是外层页面禁止滚动与内层推荐列表限高共同形成了不可达内容。

## 采用方案

使用一个自然的页面纵向滚动容器：

1. `.scene-page` 恢复纵向滚动，同时继续隐藏横向溢出；
2. `.scene-directory-compact .scene-grid-compact` 取消 200px 最大高度；
3. 推荐列表不再建立独立纵向滚动区域；
4. 保持三张卡片的顺序、内容、纵向排列、视觉样式和链接不变；
5. 保持移动端现有的单列卡片布局。

## 未采用方案

- 只恢复外层滚动：会保留页面和推荐列表两层嵌套滚动；
- 压缩上半区强行适配一屏：会破坏现有视觉层级，并且无法覆盖所有视口高度；
- JavaScript 主动滚动：问题来自静态布局约束，不需要增加运行时状态或事件监听。

## 测试与验收

先增加一个 CSS 契约测试，并确认修复前失败。测试要求：

- 场景页明确允许纵向滚动；
- 每日推荐列表不再使用固定最大高度；
- 每日推荐列表不再创建内部纵向滚动区；
- 三张推荐卡仍由 `allScenes.slice(0, 3)` 渲染。

修复后执行：

- 定向测试；
- 全部 Node 测试；
- lint；
- TypeScript typecheck；
- production build；
- 1280×720 桌面浏览器验证：页面滚到底部后第三张卡片完整可见；
- 移动视口验证：三张卡片顺序显示，页面可自然滚动，无横向溢出。

## 修改范围

- `styles.css`
- 新增或扩展一个场景页布局契约测试

不修改自由对话、实时网关、Supabase、提示词、数据库、路由或场景数据。
