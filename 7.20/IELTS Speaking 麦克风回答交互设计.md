# IELTS Speaking 麦克风回答交互设计

**日期：** 2026-07-20  
**适用项目：** `/Users/mac/Documents/七牛云/7.14/UniSpeaking_Complete_UI`  
**状态：** 待用户书面复核

## 1. 目标

将 IELTS Speaking Demo 中现有的“输入模拟转写并完成本轮”改造成真实的浏览器麦克风回答体验。考官继续按确定性题库和考试状态机提问；考生点击麦克风开始说话，可在同一轮回答内暂停和继续，点击独立的“结束本轮回答”后才提交答案并进入下一题。

本次实现覆盖 Part 1 专项、Part 2 专项、Part 3 专项和完整模拟考试。浏览器语音识别生成实时转写，用户可在提交前修正文字；无法使用语音识别时自动降级为文字输入。

## 2. 范围边界

### 2.1 本轮实现

- 浏览器主动请求麦克风权限。
- 使用 `SpeechRecognition` 或 `webkitSpeechRecognition` 进行英语实时转写。
- 提供开始、暂停、继续和结束本轮回答四个明确动作。
- 展示采集状态、回答计时、动态声波和实时/最终转写。
- 暂停后保留已有转写，继续时从末尾追加。
- 用户可手动修正转写，也可在不支持语音识别时完全手动输入。
- 本轮结束、退出考试、重新开始或离开 IELTS 页面时停止识别并释放麦克风。
- 将最终转写继续交给现有 `IeltsDemoController.submitAnswer()`，保留既有组卷、考试状态和反馈逻辑。

### 2.2 本轮不实现

- 不接入生产 Realtime Provider。
- 不上传、持久化或回放原始录音。
- 不根据浏览器转写评估 Pronunciation。
- 不实现服务端 STT、说话人分离、降噪或音频质量评分。
- 不因麦克风暂停而暂停 Part 2 准备倒计时或整场考试。

## 3. 方案选择

采用“浏览器语音识别适配器 + 可编辑转写回退”的实现。

选择原因：

- 与当前原生 ES Module、本地静态服务器架构兼容，不需要新增部署或服务端接口。
- 真实触发麦克风权限，能验证用户需要的说话、暂停、继续和结束动作。
- 核心考题仍由本地 JSON 和确定性状态机控制，不把出题权交给语音模型。
- 适配器可注入和替换，未来可换成 Realtime 或后端 STT，而不重写视图和考试状态机。

已评估但本轮不采用：

1. `MediaRecorder + 服务端 STT`：浏览器兼容和音频证据更完整，但需要上传接口、音频存储、转写服务和隐私策略。
2. 直接复用生产 Realtime：实时性更强，但会把本轮从 UI Demo 扩展为凭据、网络、会话协议和服务可用性联调。

## 4. 组件与职责

### 4.1 `SpeechRecognitionAdapter`

新增独立浏览器能力适配器，隔离厂商前缀和浏览器事件。

接口：

```js
createSpeechRecognitionAdapter({ windowRef, onInterim, onFinal, onStateChange, onError })
```

公开动作：

- `isSupported()`：检查 `SpeechRecognition` / `webkitSpeechRecognition` 和 `getUserMedia`。
- `start()`：首次由用户点击触发权限请求，成功后开始连续识别。
- `pause()`：停止当前识别会话但保留已转写内容和麦克风回答上下文。
- `resume()`：重新启动识别，将新结果追加到已有最终转写。
- `stop()`：结束识别并停止所有媒体轨道。
- `dispose()`：页面离开或控制器销毁时安全清理。

适配器不会直接修改考试状态，也不会决定何时提交回答。

### 4.2 `VoiceAnswerController`

新增本轮回答控制器，管理仅属于麦克风回答面板的临时状态：

```text
idle -> requesting_permission -> listening -> paused -> listening -> finalizing -> idle
                                    |             |
                                    +---- error --+
```

快照字段：

- `status`: `idle | requesting_permission | listening | paused | finalizing | fallback`
- `finalTranscript`: 已确认转写，可编辑。
- `interimTranscript`: 当前临时识别结果，不直接提交。
- `elapsedSeconds`: 本轮实际回答经过时间；暂停时停止累加。
- `permission`: `unknown | granted | denied`。
- `message`: 用户可读的状态或错误提示。

公开动作：

- `start()`、`pause()`、`resume()`、`updateTranscript(text)`、`finish()`、`reset()`、`dispose()`。
- `finish()` 返回合并、清理后的最终文字；空答案也允许结束，但界面需要二次确认或明确提示。

### 4.3 IELTS 视图与应用集成

现有 `ielts-answer-panel` 改为统一语音回答面板：

- 顶部显示 `YOUR ANSWER`、状态和 `MM:SS` 计时。
- 中部显示圆形主麦克风按钮和动态声波。
- 麦克风主按钮按状态显示：`开始说话`、`暂停`、`继续说话`。
- 转写区域显示最终文字和灰色临时文字，最终文字可编辑。
- 底部独立显示“结束本轮回答”。它是唯一会调用 `IeltsDemoController.submitAnswer()` 的动作。
- `fallback` 状态隐藏声波，保留文字框与“结束本轮回答”。

应用层负责把 DOM 动作转发给 `VoiceAnswerController`，再把结束结果提交给考试控制器。每当考试进入下一题时，回答控制器必须重置，不得把上题转写带入下题。

## 5. 各考试阶段行为

| 阶段 | 麦克风面板 | 允许动作 |
|---|---|---|
| Part 1 回答 | 显示 | 开始、暂停、继续、结束本轮 |
| Part 2 准备 | 不显示 | 只允许编辑准备笔记；倒计时继续 |
| Part 2 长回答 | 显示，题卡仍置顶 | 开始、暂停、继续、结束本轮 |
| Part 2 收尾问题 | 显示 | 开始、暂停、继续、结束本轮 |
| Part 3 回答 | 显示 | 开始、暂停、继续、结束本轮 |
| 报告/已退出 | 不显示并释放资源 | 无 |

完整模考中的“暂停麦克风”仅停止本轮音频采集和回答计时，不改变 `ExamState.status`，也不提供跳题、重试或暂停整场考试的能力。

## 6. 转写合并规则

- `interim` 只用于即时展示，不写入最终答案。
- 收到 `final` 时，将其按空格归一化后追加到 `finalTranscript`。
- 暂停时先保留已收到的最终结果，再停止识别。
- 继续后产生的新最终结果追加到现有文字末尾。
- 用户手工编辑后，以编辑后的 `finalTranscript` 为准；之后的新识别结果继续追加。
- 点击结束时忽略尚未确认且在短等待窗口内没有转为 final 的临时片段，避免重复提交；适配器结束事件不得触发第二次提交。
- 每轮提交最多调用一次考试控制器。

## 7. 权限、兼容性与错误处理

- 只有用户点击“开始说话”才请求权限，页面加载时不弹权限框。
- 权限拒绝：进入 `fallback`，显示“麦克风权限未开启，可直接输入回答”，不阻断考试。
- 浏览器不支持：进入 `fallback`，显示“当前浏览器不支持实时语音转写，建议使用 Chrome 或直接输入回答”。
- 识别服务临时中断：若仍处于 `listening` 且不是用户暂停，允许有限次数自动重启；连续失败后降级。
- `no-speech`：保留当前内容并提示继续说话，不清空回答。
- 麦克风设备丢失：停止轨道并降级为文字输入。
- 切换题目、退出或路由离开：必须调用 `dispose()`；迟到的识别事件通过回答轮次 token 丢弃。

## 8. 可访问性与视觉要求

- 主麦克风按钮至少 72px，移动端至少 80px；其他点击区域不低于 44px。
- 使用文字、图标和颜色共同表达状态，不能只依赖红/绿颜色。
- 主按钮包含动态 `aria-label`；状态文字使用 `aria-live="polite"`。
- 声波动画遵守 `prefers-reduced-motion`。
- 键盘用户可依次聚焦麦克风、转写区和结束按钮。
- 移动端保持“状态 → 麦克风 → 转写 → 结束本轮”的阅读顺序，不出现横向滚动。

## 9. 测试策略

### 9.1 单元测试

- 初始状态为 `idle`，首次开始只请求一次权限。
- `listening -> paused -> listening` 状态转换正确。
- 暂停后继续识别会把新 final 追加到已有转写。
- 手动编辑不会被后续 interim 覆盖。
- `finish()` 只提交一次并停止媒体轨道。
- 权限拒绝、不支持浏览器和识别错误进入文字回退。
- `dispose()` 后迟到事件不会更新下一题。

### 9.2 视图与静态契约测试

- 所有回答阶段渲染麦克风主按钮和独立结束按钮。
- Part 2 准备阶段不渲染麦克风面板。
- 完整模考仍不存在跳题、重试和整场暂停按钮。
- 视图包含状态文本、计时、可编辑转写和必要 ARIA 属性。

### 9.3 浏览器验收

1. 进入 Part 1，页面不会自动请求麦克风。
2. 点击开始后出现浏览器权限请求；允许后状态变为正在聆听。
3. 说英语时实时文字出现，暂停后文字保留且计时停止。
4. 继续说话后新内容追加；结束本轮后进入下一题。
5. Part 2 准备期间无麦克风按钮；回答阶段题卡和麦克风同时存在。
6. 拒绝权限后可输入文字并完成整场考试。
7. 390px 视口无横向溢出，按钮尺寸和键盘焦点符合要求。

## 10. 验收标准

- Part 1–3 专项和完整模考的每个回答阶段都可以真实打开麦克风。
- 用户可在同一轮回答中暂停、继续，并通过独立按钮结束本轮。
- 实时转写、手工修正和文字回退均可完成考试流程。
- Part 2 准备与回答阶段的题卡、笔记规则保持不变。
- 麦克风暂停不改变权威考试状态，不产生跳题或重复提交。
- 权限或兼容性失败不会让用户卡死。
- 自动化测试、语法检查、JSON 校验、桌面/移动端浏览器验收和控制台检查全部通过。
