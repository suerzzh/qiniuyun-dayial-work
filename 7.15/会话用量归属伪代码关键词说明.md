# 会话用量归属伪代码关键词说明

## 先说明：这是一份伪代码

伪代码的作用是说明业务流程，不是可以直接运行的程序。

例如：

```java
Client.startFreeChat(...)
```

表达的是“前端发起开始自由聊天请求”。`Client`、`startFreeChat` 等名字是为了让流程容易理解而起的示意名称，不代表百炼或某个 Java SDK 中一定存在完全相同的接口。

## 常见代码符号是什么意思

| 符号或写法 | 白话解释 | 示例 |
|---|---|---|
| `//` | 注释。只用于解释代码，程序不会执行它。 | `// 用户点击开始` |
| `=` | 把右边得到的值保存到左边的变量中。 | `User user = ...` |
| `.` | 使用某个对象拥有的功能或字段。 | `user.getId()` |
| `()` | 调用一个功能；括号里是交给这个功能的数据。 | `getId()` |
| `{}` | 表示一组需要一起执行的代码。 | `if (...) { ... }` |
| `->` | 表示“收到一个值后执行后面的代码”。 | `event -> { ... }` |
| `==` | 判断左右两边是否相同。 | `type == SESSION_CREATED` |
| `if` | 只有条件成立时，才执行大括号中的代码。 | `if (标识一致) { 保存用量 }` |
| `String` | 表示一段文字。用户 ID、会话 ID 都可以用它保存。 | `String userId` |
| `Type name` | 前面是数据类型，后面是给这份数据起的变量名。 | `User user` |

## 四个最重要的标识

| 标识 | 谁生成 | 表示什么 | 主要用途 |
|---|---|---|---|
| `user_id` | UniSpeaking 用户系统 | 当前是哪一个用户 | 决定用量最终归到谁名下 |
| `local_session_id` | UniSpeaking 后端 | UniSpeaking 自己的一次本地会话 | 在系统内部找到这次会话 |
| `provider_session_id` | 百炼 Realtime | 百炼创建的这一次 Realtime 会话 | 用来匹配千问云记录 |
| `task_uuid` | 千问云用量记录 | 千问云记录中的会话标识 | 与 `provider_session_id` 比较 |

这四个标识形成的关系是：

```text
user_id
  -> local_session_id
  -> provider_session_id
  == task_uuid
  -> usage 归入 user_id
```

## 第一部分：取得当前用户

原伪代码：

```java
User user = AuthContext.getCurrentUser()
```

### `User`

表示“一名用户”这种数据类型。里面通常会有用户 ID、昵称等信息。

### `user`

这是变量名，表示当前取得的那一名具体用户。

可以把 `User` 和 `user` 理解为：

```text
User = 用户资料这种类型
user = 当前这份具体的用户资料
```

### `AuthContext`

可以理解为“当前登录状态管理器”。它负责告诉系统现在是谁登录了。

### `.getCurrentUser()`

意思是“取得当前已经登录的用户”。

整行翻译成白话：

```text
从登录状态中找到当前用户，并把这个用户保存到名为 user 的变量中。
```

### `user.getId()`

意思是“从当前用户资料中取出用户唯一 ID”。

本次测试中取出的值是：

```text
demo-user-001
```

## 第二部分：开始自由聊天

原伪代码：

```java
Client.startFreeChat(
        StartFreeChatRequest.builder()
            .setUserId(
                user.getId()
            )
            .build()
)
```

### `Client`

表示 UniSpeaking 客户端，也就是用户正在操作的网页或 App。

### `.startFreeChat(...)`

表示“发起开始自由聊天的请求”。

括号里的内容是本次开始请求需要携带的数据。

### `StartFreeChatRequest`

表示“开始自由聊天请求”这种数据结构。

它的作用是把开始会话需要的信息装在一起，再交给后端。

### `.builder()`

表示“开始一步步组装一份请求”。

可以把它想象成先拿到一张空表格，接下来逐项填写用户 ID、场景类型等内容。

### `.setUserId(...)`

表示“把用户 ID 填入这份请求”。

例如：

```java
.setUserId(
    user.getId()
)
```

执行过程是：

```text
先通过 user.getId() 取得 demo-user-001
再把 demo-user-001 填入请求的 userId 字段
```

它的目的，是让后端知道这次开始的会话属于哪个用户。

### `.build()`

表示“所有字段填写完成，生成最终请求对象”。

整体可以理解为：

```text
创建开始请求
  -> 填写用户 ID
  -> 完成请求
  -> 发送给后端
```

## 第三部分：创建 UniSpeaking 本地会话

原伪代码：

```java
LocalSession localSession =
        LocalSessionFactory.create(
                LocalSessionRequest.builder()
                    .setUserId(
                        user.getId()
                    )
                    .setSceneType(
                        SceneType.FREE_CHAT
                    )
                    .build()
        )
```

### `LocalSession`

表示 UniSpeaking 自己管理的一次本地会话。

它和百炼的 Realtime 会话不是同一个东西：

```text
LocalSession = UniSpeaking 内部会话
百炼 session = 百炼服务端会话
```

### `localSession`

保存刚创建出来的那一次具体本地会话。

### `LocalSessionFactory`

可以理解为“本地会话生产器”。它专门负责按照给定信息创建一条新会话。

### `.create(...)`

表示“根据括号里的请求内容创建本地会话”。

### `LocalSessionRequest`

表示“创建本地会话需要的数据”。其中至少包含用户 ID 和场景类型。

### `.setSceneType(...)`

表示“设置本次会话属于什么业务场景”。

### `SceneType`

表示系统支持的场景类型集合，例如自由聊天、面试训练或 IELTS 训练。

### `SceneType.FREE_CHAT`

表示本次场景是“自由聊天”。

其中：

```text
SceneType = 场景类型集合
FREE_CHAT = 集合中的自由聊天类型
```

### `localSession.getId()`

表示“取得 UniSpeaking 刚创建的本地会话 ID”。

本次真实值是：

```text
3a957e96064445babdf00d05cb418110
```

## 第四部分：保存用户和本地会话的关系

原伪代码：

```java
SessionRepository.save(
        SessionRecord.builder()
            .setUserId(
                user.getId()
            )
            .setLocalSessionId(
                localSession.getId()
            )
            .build()
)
```

### `SessionRecord`

表示一条“会话关系记录”。它用来保存这次会话属于谁、有哪些标识。

### `.setLocalSessionId(...)`

表示“把 UniSpeaking 本地会话 ID 写入记录”。

### `SessionRepository`

可以理解为“会话记录仓库”，负责保存和查找会话记录。

在真正的项目中，它的底层通常是数据库。

### `.save(...)`

表示“把括号里的记录保存下来”。

这一阶段保存的是：

```text
user_id -> local_session_id
```

此时还没有取得百炼的 `provider_session_id`。

## 第五部分：连接百炼 Realtime

原伪代码：

```java
RealtimeConnection connection =
        QwenRealtimeClient.connect(
                RealtimeConnectRequest.builder()
                    .setLocalSessionId(
                        localSession.getId()
                    )
                    .build()
        )
```

### `RealtimeConnection`

表示浏览器与百炼 Realtime 服务之间建立的实时连接。

语音、服务端事件和 AI 回复都会通过这条连接传输。

### `connection`

保存这一次具体的实时连接，后面需要通过它监听百炼事件。

### `QwenRealtimeClient`

表示“用于连接百炼 Realtime 的客户端”。

### `.connect(...)`

表示“开始建立 Realtime 连接”。

### `RealtimeConnectRequest`

表示“建立 Realtime 连接所需的数据”。

### 为什么设置 `localSessionId`

百炼并不认识 UniSpeaking 的本地会话 ID，但 UniSpeaking 自己需要知道当前正在建立的百炼连接对应哪条本地会话。

这样稍后收到 `session.created` 时，才能把百炼 ID 绑定到正确的本地会话。

## 第六部分：监听 `session.created`

原伪代码：

```java
connection.onEvent(event -> {
    if (event.getType() == EventType.SESSION_CREATED) {
        String providerSessionId =
                event.getSession().getId()
    }
})
```

### `.onEvent(...)`

表示“开始监听百炼通过 Realtime 连接发来的事件”。

### `event`

表示百炼当前发来的某一个具体事件。

### `event -> { ... }`

意思是：

```text
每当收到一个 event
就执行大括号中的代码
```

### `event.getType()`

表示“取得这个事件的类型”。

### `EventType.SESSION_CREATED`

表示百炼的“会话创建成功”事件类型，也就是：

```text
session.created
```

### `event.getSession()`

表示“从事件中取得百炼返回的 session 对象”。

### `event.getSession().getId()`

可以拆成两步理解：

```text
event.getSession() = 取得 session
session.getId() = 取得 session 里面的 id
```

最终取得的就是：

```text
session.created.session.id
```

本次真实值为：

```text
sess_CQEnIAvxbwqto5CFOIoEh
```

### `providerSessionId`

这是 UniSpeaking 为百炼 `session.id` 起的变量名。

它表示“供应商侧的会话 ID”，后面会用它匹配千问云的 `task_uuid`。

## 第七部分：把百炼会话 ID 提交给后端

原伪代码：

```java
Client.bindProviderSession(
        BindProviderSessionRequest.builder()
            .setLocalSessionId(
                localSession.getId()
            )
            .setProviderSessionId(
                providerSessionId
            )
            .build()
)
```

### `.bindProviderSession(...)`

表示“请求后端把百炼会话 ID 绑定到 UniSpeaking 本地会话”。

### `BindProviderSessionRequest`

表示“绑定百炼会话 ID”所需的数据。

它同时携带：

```text
local_session_id
provider_session_id
```

### `.setProviderSessionId(...)`

表示“把从 `session.created` 中取得的百炼会话 ID 填入绑定请求”。

### 为什么两个 ID 都要提交

只有 `provider_session_id`，后端不知道它属于哪条 UniSpeaking 会话。

同时提交两个 ID 后，后端才能建立：

```text
local_session_id -> provider_session_id
```

而 `local_session_id` 之前已经绑定了 `user_id`，所以完整关系就能连起来。

## 第八部分：后端保存完整关系

原伪代码：

```java
BindProviderSessionRequest bindRequest =
        Server.receiveBindProviderSessionRequest()

SessionRecord sessionRecord =
        SessionRepository.findByLocalSessionId(
                bindRequest.getLocalSessionId()
        )

sessionRecord.setProviderSessionId(
        bindRequest.getProviderSessionId()
)

SessionRepository.save(
        sessionRecord
)
```

### `Server`

表示 UniSpeaking 后端服务。

### `.receiveBindProviderSessionRequest()`

表示“后端接收前端发送的绑定请求”。

### `bindRequest`

表示后端实际收到的那一份绑定请求。

### `bindRequest.getLocalSessionId()`

表示“从绑定请求中取出本地会话 ID”。

### `.findByLocalSessionId(...)`

表示“按照本地会话 ID 查找已经保存的会话记录”。

### `sessionRecord`

表示后端从会话仓库中找到的那条具体记录。

这条记录之前已经包含：

```text
user_id
local_session_id
```

### `bindRequest.getProviderSessionId()`

表示“从绑定请求中取出百炼会话 ID”。

### `sessionRecord.setProviderSessionId(...)`

表示“把百炼会话 ID 补充到原来的用户会话记录中”。

保存后形成：

```text
user_id
  -> local_session_id
  -> provider_session_id
```

## 第九部分：结束会话

原伪代码：

```java
Client.waitForProviderSessionBinding(
        localSession.getId()
)

Client.endFreeChat(...)

SessionService.closeSession(
        localSession.getId()
)
```

### `.waitForProviderSessionBinding(...)`

表示“结束之前，先等待百炼会话 ID 的绑定请求完成”。

这样可以避免用户很快结束会话时，关闭请求先到、绑定请求后到，导致标识没有保存成功。

### `.endFreeChat(...)`

表示“前端发起结束自由聊天请求”。

### `EndFreeChatRequest`

表示“结束会话请求”。其中包含需要结束的本地会话 ID。

### `SessionService`

表示后端负责管理会话生命周期的服务。

### `.closeSession(...)`

表示“把这条本地会话标记为已结束”。

会话结束不等于删除标识关系。后续查用量仍然需要保存：

```text
user_id -> local_session_id -> provider_session_id
```

## 第十部分：按照 `task_uuid` 查找用量

原伪代码：

```java
UsageRecord cloudUsageRecord =
        QwenUsageLogService.findByTaskUuid(
                sessionRecord.getProviderSessionId()
        )
```

### `UsageRecord`

表示千问云产生的一条用量记录。

### `cloudUsageRecord`

表示系统从千问云查到的那条具体用量记录。

### `QwenUsageLogService`

表示“负责查询千问云用量日志的服务”。

### `.findByTaskUuid(...)`

表示“按照 `task_uuid` 查找千问云记录”。

传进去的是本地保存的 `provider_session_id`：

```text
sess_CQEnIAvxbwqto5CFOIoEh
```

等价于在千问云中查找：

```text
task_uuid = sess_CQEnIAvxbwqto5CFOIoEh
```

### `sessionRecord.getProviderSessionId()`

表示“从用户会话记录中取出之前保存的百炼会话 ID”。

## 第十一部分：判断两个标识是否一致

原伪代码：

```java
if (cloudUsageRecord.getTaskUuid().equals(
        sessionRecord.getProviderSessionId()
)) {
    ...
}
```

### `cloudUsageRecord.getTaskUuid()`

表示“从千问云用量记录中取出 `task_uuid`”。

### `.equals(...)`

表示“比较两段文字是否完全一致”。

这里比较的是：

```text
千问云 task_uuid
本地 provider_session_id
```

本次实际比较为：

```text
sess_CQEnIAvxbwqto5CFOIoEh
==
sess_CQEnIAvxbwqto5CFOIoEh
```

结果一致，所以确认是同一次会话。

## 第十二部分：把用量归到用户下

原伪代码：

```java
UserUsageRecord userUsageRecord =
        UserUsageRecord.builder()
            .setUserId(...)
            .setLocalSessionId(...)
            .setProviderSessionId(...)
            .setTaskUuid(...)
            .setUsage(...)
            .build()

UserUsageRepository.save(
        userUsageRecord
)
```

### `UserUsageRecord`

表示 UniSpeaking 自己保存的一条“用户用量记录”。

### `userUsageRecord`

表示这次准备保存的具体用户用量记录。

### `.setUserId(...)`

写入用户 ID，明确本次用量归到哪个用户。

### `.setLocalSessionId(...)`

写入 UniSpeaking 本地会话 ID，方便从系统内部追踪这次对话。

### `.setProviderSessionId(...)`

写入百炼会话 ID，保留与百炼 Realtime 会话的对应关系。

### `.setTaskUuid(...)`

写入千问云记录中的 `task_uuid`，保留云端日志匹配结果。

### `.setUsage(...)`

写入千问云返回的本次会话用量数据。

### `cloudUsageRecord.getUsage()`

表示“从千问云用量记录中取出 usage 内容”。

### `UserUsageRepository`

可以理解为“用户用量记录仓库”，负责保存和查询每个用户的用量。

### `UserUsageRepository.save(...)`

表示“把最终组装好的用户用量记录保存到数据库”。

保存后，系统就能按 `user_id` 汇总这个用户的全部会话用量。

## 最后用一句白话串起来

```text
先取得当前用户
  -> 创建属于该用户的本地会话
  -> 从百炼 session.created 中取得 provider_session_id
  -> 把 provider_session_id 保存到用户的本地会话下
  -> 会话结束后，用 provider_session_id 查询 task_uuid 相同的千问云记录
  -> 取得这条记录的 usage
  -> 把 usage 保存到原来的 user_id 名下
```
