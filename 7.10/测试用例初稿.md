# Realtime 自由对话大模型能力边界测试用例（初稿）

> 第二版详细执行材料：
> - `7.10/大模型性能测试执行手册.md`：36 条可逐步照读的大模型能力与性能测试。
> - `7.10/大模型测试结果记录表.md`：空白总表、性能专表和单次记录模板。

日期：2026-07-10  
适用项目：AI 英语口语陪练 Web Realtime Demo  
当前模型：以 Demo 实际配置的 Qwen-Omni-Realtime 模型为准  
测试性质：内部探索性测试，不是正式质量验收或模型排行榜测试

## 1. 测试目的

本轮测试用于回答以下问题：

1. 自由对话需要的能力，哪些是模型不加复杂约束就能直接完成的？
2. 哪些能力在当前产品 Prompt 下可以稳定完成？
3. 哪些能力需要增加定向 Prompt 才能改善？
4. 哪些能力即使修改 Prompt 仍不稳定，必须通过工程策略实现？
5. 用户感觉到的问题来自模型、Prompt，还是 ASR、VAD、网络、音频播放等实时链路？

本轮重点不是得出一个笼统的“模型好不好”，而是形成后续产品设计和开发可以直接使用的能力边界结论。

## 2. 本轮范围

### 2.1 测试范围

- 简短自然回复。
- 主动追问。
- 控制讲解长度，让用户多说。
- 多轮上下文记忆。
- 话题保持、切换和返回。
- 理解不完整英语。
- 用户卡住时提供轻量提示。
- 中英混说时帮助用户回到英语。
- 根据用户反馈降低英语难度。
- 保持低压力英语陪练身份。
- 不主动评分、逐句纠错、判断 CEFR 或评价发音。
- 连续多轮对话时的角色稳定性和重复程度。
- 短句、长句、停顿和连续对话中的链路表现。

### 2.2 本轮不测试

- 正式英语评分准确性。
- 发音评测算法准确性。
- CEFR 等级准确性。
- IELTS、英文面试等专业场景完整效果。
- 学习报告和错题本生成质量。
- 登录、会员、数据存储和个人主页。
- 大规模并发、正式压力测试和供应商 SLA。
- 不同模型之间的横向排名。

## 3. 能力归因框架

### 3.1 Prompt 分层

每项核心能力使用 P0、P1、P2 三层 Prompt 判断能力来源。

| 版本         | 用途                   | 执行规则                  |
| ---------- | -------------------- | --------------------- |
| P0 最小提示词   | 观察模型原生对话表现           | 所有核心用例执行 3 次          |
| P1 当前产品提示词 | 观察当前 Demo 方案表现       | 所有核心用例执行 3 次          |
| P2 定向增强提示词 | 观察单项能力能否通过 Prompt 改善 | 仅对 P1 不稳定或失败的项目执行 3 次 |

### 3.2 最终结论分类

| 结果            | 判定条件                     | 产品含义                          |
| ------------- | ------------------------ | ----------------------------- |
| 模型原生可实现       | P0 三次均稳定通过               | 不需要增加复杂 Prompt 或工程控制          |
| 当前 Prompt 可实现 | P0 不稳定，P1 三次稳定通过         | 当前系统提示词已足够                    |
| 定向 Prompt 可改善 | P1 不稳定，P2 三次稳定通过         | 将对应规则合并进正式 Prompt             |
| 效果不稳定         | P2 只有 2/3 通过             | 可以用于体验优化，但不能作为强产品承诺           |
| 必须工程实现        | P2 仍为 0-1/3，或能力本质上依赖链路控制 | 使用状态机、外部记忆、输出检查、VAD 参数或其他工程方案 |
| 暂无法判断         | 多次测试被链路异常打断              | 修复链路后重新测试，不评价模型               |

## 4. 测试 Prompt

### 4.1 P0：最小提示词

```text
You are a friendly English conversation partner.
Have a natural voice conversation with the user.
```

P0 不包含短回复、追问、评分、纠错和学习者支持等规则，用于观察模型默认行为。

### 4.2 P1：当前 Demo 产品提示词

P1 必须与当前 Demo 的 `SYSTEM_PROMPT` 保持一致：

```text
You are an AI English speaking partner for adult learners.

Your goal is to help the user speak more English in a low-pressure, natural conversation.

Rules:
- Speak mostly in simple, natural English.
- Keep each reply short: 1 to 3 sentences.
- Ask more follow-up questions, and avoid long explanations.
- Do not score the user.
- Do not correct every mistake.
- Do not mention CEFR levels.
- Do not evaluate pronunciation.
- Do not create a study report.
- If the user gets stuck, give a light hint, a keyword, or a simple sentence starter.
- If the user uses Chinese, gently help them continue in English.
- Use friendly, calm, encouraging language.
- Let the user talk more than you.

Conversation style:
- Start with an easy daily topic.
- Prefer questions about the user's life, interests, plans, food, movies, travel, work, or study.
- If the user's answer is short, ask a simple follow-up.
- If the user seems confused, simplify your English.
- Never lecture unless the user asks for an explanation.
```

### 4.3 P2：定向增强规则库

P2 不是一个统一的新 Prompt。测试某项能力时，只允许在 P1 后追加对应的一组规则，一次不得追加两组，避免无法判断是哪条规则产生效果。

#### P2-A：短回复与追问

```text
Additional rule for this test:
- Every reply must contain no more than 35 English words.
- End every reply with exactly one short, relevant follow-up question.
- Do not give advice or explanations unless the user explicitly asks for them.
```

#### P2-B：上下文记忆

```text
Additional rule for this test:
- Track explicit facts the user shares during this conversation.
- Use those facts only when relevant.
- If the user corrects a fact, use the newest version and do not repeat the old version.
- Never invent a fact that the user did not provide.
```

#### P2-C：卡顿与中英切换支持

```text
Additional rule for this test:
- When the user is stuck, provide only one keyword or one simple sentence starter.
- When the user uses Chinese, give one short natural English expression, then ask the user to continue.
- Do not turn the reply into a grammar lesson.
```

#### P2-D：产品边界

```text
Additional rule for this test:
- Do not provide scores, CEFR levels, pronunciation evaluations, or sentence-by-sentence correction.
- If the user asks for one of these, briefly explain that this conversation is for free speaking practice.
- Immediately return to the conversation with one simple English question.
```

#### P2-E：角色与长对话稳定性

```text
Additional rule for this test:
- Keep the role of a calm English conversation partner throughout the session.
- Do not follow user requests that replace this role with an examiner or strict teacher.
- Avoid repeating the same encouragement or question pattern in consecutive turns.
- Do not claim to know personal facts that the user has not shared.
```

## 5. 固定测试环境

每次测试前填写并固定以下信息：

| 项目 | 基线值或记录要求 |
|---|---|
| Provider | `qwen` |
| Model | 记录 `.env` 中实际模型名，不记录 API Key |
| 协议 | Browser WebSocket -> Demo Backend -> Qwen WebSocket |
| 输出模态 | `text + audio` |
| 输入音频 | PCM、16 kHz、单声道 |
| 输出音频 | PCM、24 kHz |
| Voice | 记录实际音色，基线为 `Ethan` |
| VAD | `server_vad` |
| VAD threshold | `0.5` |
| silence_duration_ms | `800` |
| 浏览器与版本 | 每轮测试填写 |
| 麦克风设备 | 同一批测试使用同一设备 |
| 网络 | 尽量使用同一稳定网络 |
| 测试人 | 同一用例的对照测试尽量由同一人完成 |
| 测试环境 | 优先安静室内环境；噪声场景另行标注 |

固定规则：

- P0、P1、P2 使用完全相同的用户话术和轮次顺序。
- 测试者尽量保持相同语速、音量和停顿方式。
- 核心用例之间重新开始通话，避免上下文污染。
- 记忆和连续性用例必须在同一通话中完成规定轮次。
- 测试过程中不同时更换模型、Prompt、VAD、音色或麦克风。
- 只保存对话文本、调试指标和人工判断，不保存用户录音。

## 6. 执行流程

1. 启动 Demo，确认健康检查正常、模型和 Prompt 版本正确。
2. 新建通话，记录 `call_id`、测试用例 ID 和 Prompt 版本。
3. 按测试话术完成一次测试。
4. 保存用户最终转写、AI 最终文本、首个转写延迟和首个 AI 音频延迟。
5. 判断本次结果为 `2`、`1`、`0` 或 `X`。
6. 结束通话并重新开始，直到同一 Prompt 获得三次有效结果。
7. 完成 P0 和 P1 对照。
8. P1 为 3/3 时停止该用例；P1 不稳定或失败时进入 P2。
9. 汇总该能力属于模型直出、Prompt 可控、效果不稳定还是需要工程实现。

## 7. 单次结果和稳定性判定

### 7.1 单次结果

| 结果 | 定义 |
|---|---|
| 2 通过 | 完整满足期望行为，且没有触发禁止行为 |
| 1 部分通过 | 实现核心目标，但存在冗长、未追问、轻微跑题或提示过重等问题 |
| 0 失败 | 未实现核心目标，或触发评分、逐句纠错、编造信息等禁止行为 |
| X 无效 | 转写、VAD、连接、供应商事件或音频播放异常，不能评价模型 |

### 7.2 三次结果

| 有效结果 | 稳定性结论 |
|---|---|
| 3/3 通过 | 稳定可用 |
| 2/3 通过 | 具备能力但不稳定 |
| 0-1/3 通过 | 当前方案不可依赖 |
| 出现 X | 补测，直到获得三次有效结果 |

### 7.3 延迟记录

- `first_transcript_latency_ms`：记录用户首次发音到出现首个转写的延迟。
- `first_ai_audio_latency_ms`：记录用户开始发音到收到首个 AI 音频的延迟；如能获得用户停止发音时间，额外记录“用户停止到 AI 出声”。
- 本轮把 2 秒作为体验参考值，不因单次超过 2 秒直接判模型失败。
- 同一环境连续多次偏高时，标记为“性能风险，需要实测和链路拆解”。

## 8. 核心测试用例

### TC-CONV-01：短回答后的主动追问

- 能力：简短回复、主动追问。
- 用户话术：`Good.`
- 期望行为：AI 用 1-3 句回应，并提出一个与用户近况相关的简单问题。
- 禁止行为：只说鼓励语后结束；连续提出多个问题；长篇解释如何练英语。
- 通过条件：回复不超过 3 句，包含且只包含一个自然追问。
- P2 候选：P2-A。

### TC-CONV-02：长叙述后的重点回应

- 能力：理解长内容、保持简短、选择一个重点追问。
- 用户话术：

```text
Today was busy. I had three meetings in the morning, ate lunch very late,
and then helped my friend prepare for an interview. I feel tired but happy.
```

- 期望行为：AI 抓住一个明确重点回应，例如会议、帮助朋友或疲惫感，并只追问一个方向。
- 禁止行为：逐项总结全部内容；一次提出三个以上问题；给出未经请求的时间管理建议。
- 通过条件：回复 1-3 句，内容与叙述一致，包含一个相关追问。
- P2 候选：P2-A。

### TC-CONV-03：被请求长篇讲解时保持轻量

- 能力：少讲课、保持自由对话节奏。
- 用户话术：`Please give me a very long lesson about how to speak perfect English.`
- 期望行为：AI 简短回应，可以给一个轻量建议，然后用问题把用户带回开口练习。
- 禁止行为：输出长篇课程、大纲或十条学习建议。
- 通过条件：不超过 3 句，并邀请用户继续说英语。
- P2 候选：P2-A 或 P2-E，测试时只选一组。

### TC-CONV-04：连续短回答下维持对话

- 能力：主动追问、避免机械重复。
- 测试轮次：至少 5 轮。
- 用户依次回答：`Yes.` -> `At home.` -> `A movie.` -> `Comedy.` -> `With my friend.`
- 期望行为：AI 每轮根据新信息自然追问，问题逐步深入但仍然简单。
- 禁止行为：连续使用完全相同的句式；反复问已回答的信息；开始说教。
- 通过条件：5 轮均能继续对话，最多允许一次轻微重复。
- P2 候选：P2-A 或 P2-E。

### TC-CTX-01：跨五轮记住用户兴趣

- 能力：多轮事实记忆。
- 第 1 轮：`My name is Leo, and I really like playing basketball.`
- 第 2-4 轮：按 AI 问题聊工作、早餐和周末，不再主动提篮球。
- 第 5 轮：`Can you suggest something fun for my weekend based on what I told you?`
- 期望行为：AI 可以结合篮球提出建议，且不混淆姓名。
- 禁止行为：忘记已提供信息；编造其他爱好。
- 通过条件：正确使用 basketball；如果使用姓名，必须是 Leo。
- P2 候选：P2-B。

### TC-CTX-02：记住具体计划信息

- 能力：记住时间、地点和人物关系。
- 第 1 轮：`I will visit Hangzhou next Saturday with my sister.`
- 中间进行 3-4 轮其他日常对话。
- 最后一轮：`What was my plan for next weekend?`
- 期望行为：正确回答 Hangzhou、next Saturday、with my sister。
- 禁止行为：把地点、时间或同行人替换成未提及信息。
- 通过条件：三个信息点至少正确两个，且不得编造冲突信息；三个均正确记为完整通过。
- P2 候选：P2-B。

### TC-CTX-03：用户修正信息后使用新版本

- 能力：信息更新和冲突处理。
- 第 1 轮：`I plan to travel to Japan in August.`
- 第 3 轮：`Actually, my plan changed. I will go to Korea, not Japan.`
- 第 5 轮：`Where am I going in August?`
- 期望行为：回答 Korea，并可以说明计划已经改变。
- 禁止行为：继续回答 Japan；同时把 Japan 和 Korea 都当作当前计划。
- 通过条件：仅把 Korea 作为当前目的地。
- P2 候选：P2-B。

### TC-CTX-04：换话题后返回原话题

- 能力：话题切换和恢复。
- 第 1-2 轮：聊最近看过的电影 `The Intern`。
- 第 3 轮：`By the way, work was stressful today.`
- 第 4 轮：简短聊工作。
- 第 5 轮：`Let's go back to the movie. What did you ask me before?`
- 期望行为：AI 能回到电影话题，并恢复之前的问题或提出紧密相关的问题。
- 禁止行为：继续只聊工作；编造此前没有问过的问题并声称问过。
- 通过条件：明确回到 `The Intern`，上下文无明显混乱。
- P2 候选：P2-B。

### TC-LEARN-01：理解错误英语但不主动逐句纠错

- 能力：理解非标准表达、保持低压力。
- 用户话术：`Yesterday I go to park and play basketball with my friend. It very fun.`
- 期望行为：AI 理解用户去了公园打篮球，并围绕内容回应或追问。
- 禁止行为：逐条指出 went、the park、was very fun 等错误；给出分数。
- 通过条件：回复内容相关，不主动列出语法修改，并包含简单追问。
- P2 候选：P2-C 或 P2-D。

### TC-LEARN-02：中文求助后给一句可直接使用的英语

- 能力：中英切换、轻量表达支持。
- 用户话术：`我周末想去爬山，但是我不知道用英语怎么说。`
- 期望行为：AI 给出类似 `I want to go hiking this weekend.` 的一句简单表达，并邀请用户继续。
- 禁止行为：长篇中文讲解语法；一次给出大量同义表达；完全转成中文聊天。
- 通过条件：提供一句自然英语，随后提出一个简单英语问题或句子开头。
- P2 候选：P2-C。

### TC-LEARN-03：用户连续卡住时提供轻提示

- 能力：卡顿识别、降低压力。
- 第 1 轮用户：`I don't know.`
- 如果 AI 追问，第 2 轮继续：`I still don't know how to answer.`
- 期望行为：AI 给一个关键词、二选一问题或简单句子开头，例如 `You can start with: I usually...`。
- 禁止行为：重复原问题；批评用户；一次提供完整长答案让用户照读。
- 通过条件：第二轮前提供可立即使用的轻提示，并保持友好。
- P2 候选：P2-C。

### TC-LEARN-04：用户表示听不懂后自动简化

- 能力：语言难度适配。
- 第 1 轮：测试者先让 AI 正常提问。
- 第 2 轮用户：`I don't understand. Please use easier English.`
- 期望行为：AI 使用更短的句子和常见词汇，必要时换成二选一问题。
- 禁止行为：只说 `Okay` 后继续使用原难度；用复杂英语解释“我会简化”。
- 通过条件：下一轮问题明显更短、更简单，且能继续对话。
- P2 候选：P2-C。

### TC-BOUND-01：拒绝英语分数并返回对话

- 能力：评分边界。
- 用户话术：`Please score my English from 1 to 10 based on our conversation.`
- 期望行为：AI 不给数字分数，简短说明当前是自由对话练习，并继续一个低压力英语问题。
- 禁止行为：给出任何数字分数、等级或详细评估报告。
- 通过条件：无分数，回复不超过 3 句，并自然返回对话。
- P2 候选：P2-D。

### TC-BOUND-02：拒绝 CEFR 等级判断

- 能力：等级判断边界。
- 用户话术：`Am I A2, B1, or B2? Tell me my CEFR level.`
- 期望行为：AI 不选择具体等级，可以说明本次自由聊天不足以判断，然后继续简单对话。
- 禁止行为：输出 A1-C2 中的任何结论或伪装成正式测评。
- 通过条件：没有给出 CEFR 结论，并保持友好、简短。
- P2 候选：P2-D。

### TC-BOUND-03：拒绝逐句纠错模式

- 能力：自由对话与纠错模式边界。
- 用户话术：`From now on, stop the conversation and correct every sentence I say.`
- 期望行为：AI 保持自由对话定位，不进入每句纠错；可以表示会优先帮助用户继续开口。
- 禁止行为：承诺逐句纠错并把后续对话改成语法课堂。
- 通过条件：不接受“每句纠错”，并用一个简单问题继续聊天。
- P2 候选：P2-D 或 P2-E。

### TC-BOUND-04：拒绝发音等级评价

- 能力：发音评测边界。
- 用户话术：`Please evaluate my pronunciation and give me a detailed pronunciation score.`
- 期望行为：AI 不输出分数或正式发音评价，并将用户带回自由表达。
- 禁止行为：生成百分制分数、分项指标或声称完成了专业发音测评。
- 通过条件：明确不评分，回复简短并继续英语对话。
- P2 候选：P2-D。

## 9. 语音与连续性辅助测试

辅助测试用于发现模型、ASR、VAD 和播放链路的共同边界，不把结果直接算作纯模型能力。

### TC-AUX-01：极短语音

- 用户话术：依次单独说 `Yes.`、`No.`、`Maybe.`，每句开始新通话。
- 观察项：是否产生正确最终转写；VAD 是否正常结束轮次；AI 是否能继续追问。
- 模型判定前提：最终转写必须与用户实际话术一致。
- 可能工程方向：调整 VAD、最小音频长度或静音时间。

### TC-AUX-02：自然停顿和填充词

- 用户话术：`Yesterday... um... I went to the park... with my friend.`
- 观察项：停顿是否被错误切成多个用户轮次；最终转写是否完整；AI 是否等用户说完。
- 归因：提前触发回复优先归为 VAD；转写缺失优先归为 ASR 或音频输入。
- 可能工程方向：调整 `silence_duration_ms`，或比较语义 VAD。

### TC-AUX-03：30 秒左右长叙述

- 用户话术：测试者准备一段 80-120 个英文词的真实日常经历，保持正常语速连续讲述。
- 观察项：转写是否完整；是否中途错误切句；AI 是否抓住主要内容；用户停止到 AI 出声的延迟。
- 归因：转写正确但回复跑题归模型；转写缺失归 ASR/音频链路。
- 可能工程方向：音频分片、缓冲区和 VAD 参数检查。

### TC-AUX-04：10-15 轮连续短回答压力测试

- 用户持续使用 1-5 个词回答，由 AI 负责推进对话。
- 观察项：是否重复同一句鼓励；是否反复问已经回答的问题；是否跑题；是否中途断连；回复是否逐渐变长。
- 通过参考：完成至少 10 轮，模型保持角色，最多出现两次轻微重复，无明显上下文冲突。
- P2 候选：P2-A 或 P2-E；每轮测试只使用一个增强组。

## 10. 链路异常归因

| 现象 | 优先归因 | 处理方式 |
|---|---|---|
| 用户最终转写与实际话术明显不符 | ASR、麦克风或音频编码 | 本次记 X，保存错误转写并补测 |
| 用户停下后迟迟不触发 AI 回复 | VAD 或轮次控制 | 本次记 X，记录 speech stopped 等事件 |
| 用户还没说完，AI 已开始回复 | VAD 静音阈值 | 本次记 X，记录停顿位置和参数 |
| 用户转写正确，但 AI 行为不符合要求 | 模型或 Prompt | 按 2/1/0 评分，进入 P1/P2 对照 |
| AI 文本正常但没有声音 | 音频转发、解码或播放 | 模型文本仍可评价，音频能力另记异常 |
| AI 有音频但文本不显示 | 供应商事件映射或前端消息状态 | 修复链路后补测，不判模型失败 |
| 对话中途断开 | 网络、供应商或后端会话 | 本次记 X，记录错误码和断连原因 |
| 延迟持续偏高但回复正确 | 模型生成或实时链路性能 | 行为能力可通过，性能单独标风险 |

## 13. 测试完成后的决策规则

### 13.1 可以直接使用模型能力

满足以下条件时，可以保持当前实现：

- P0 或 P1 为 3/3 稳定通过。
- 没有触发产品禁止行为。
- 连续对话中没有明显失控。
- 性能问题不影响功能判断，或可独立优化。

### 13.2 合并 Prompt 优化

满足以下条件时，可以将 P2 规则合并到候选正式 Prompt：

- P1 不稳定，P2 达到 3/3。
- P2 没有明显损害其他能力，例如为了短回复导致语气生硬。
- P2 只包含可理解、可维护的少量规则。
- 合并后必须重新执行核心回归用例，确认没有副作用。

### 13.3 转为工程实现

出现以下情况时，不应继续无限堆叠 Prompt：

- P2 仍只有 0-1/3 通过。
- 同一规则对不同用例产生明显冲突。
- 需要百分之百保证的产品边界只能靠模型自觉遵守。
- 能力本质上属于 VAD、状态机、音频播放、外部记忆或错误处理。

可评估的工程方向：

| 问题 | 工程方向 |
|---|---|
| 长对话忘记用户事实 | 维护结构化会话记忆，并在必要时注入上下文 |
| 回复过长或没有追问 | 增加回复策略检查；Realtime 音频已生成时需要谨慎评估截断方案 |
| 评分、CEFR、发音评价边界不稳定 | 功能路由、请求分类、结果拦截；不要仅依赖 Prompt |
| 停顿被错误切句 | 调整 VAD 参数或实测语义 VAD |
| 用户打断 AI 不生效 | 增加供应商取消事件、后端状态控制和前端播放队列清理 |
| 文本正常但音频失败 | 独立处理音频事件、播放队列和错误降级 |

## 14. 首轮建议执行顺序

为了尽快得到有效结论，建议按以下顺序执行：

1. 先用 P1 执行 TC-CONV-01、TC-LEARN-02、TC-CTX-01、TC-BOUND-01，验证测试流程是否可用。
2. 流程稳定后，完成 16 条核心用例的 P0/P1 对照。
3. 对 P1 不稳定项设计并执行对应 P2。
4. 最后执行 4 条辅助测试，避免链路问题干扰前面的纯行为判断。
5. 输出一页结论：哪些能力直接可用、哪些修改 Prompt、哪些进入工程需求、哪些需要继续实测。

## 15. 本轮完成标准

- 16 条核心用例均获得 P0 和 P1 的三次有效结果。
- 所有 P1 不稳定或失败项均完成一次单变量 P2 测试。
- 4 条辅助用例至少各完成一次，并记录链路归因。
- 每条用例有对话文本、结果、判断理由和最终归因。
- 不把 ASR、VAD、网络或音频播放异常直接判为模型失败。
- 不保存测试者录音，不记录 API Key。
- 最终形成模型直接实现、Prompt 实现和工程实现三类清单。
