# Findings: Realtime Control & Audit

## Source Intent
- 单页技术控制与审计流程图。
- 核心观点：后端统一控制主 Key，前端只保留 WebRTC 连接；业务后端是控制中心，用量台账用于实时管理，官方 JSON 用于最终审计。

## Visual Structure
- 16:9 暖白底，橙红、青绿、黑灰三色。
- 上方为眉题、主标题、说明句。
- 中部为浏览器、业务后端、阿里云 Token、Realtime、用量台账、官方 JSON 六个节点及多色箭头。
- 下方为浏览器可见/不可见说明、五段 ID 链路和右侧审计结论。

## Editable Boundary
- 框、线、箭头、节点、强调色文字片段和底部节点均拆分为原生 PowerPoint 对象。
- 不使用整页或整层图片。

## Source Geometry
- 源图 1672×941（16:9），暖白背景。
- 六个主卡片坐标已记录在本次 RUN_ROOT 的 `source-geometry.txt`。
- 页面没有必须保留为位图的插画，因此可实现最终图片对象数为 0。
- 颜色基准：橙红 `#F24C2E`、青绿 `#138F8C`、深色 `#191A1B`、浅边框 `#B9B1A7`、背景 `#FBF8F2`。

## First native preview review
- 六个主卡片、连线方向、虚线对账、浏览器说明区和底部 ID 链路的位置已与源图基本一致。
- 第一版标题、眉题、说明句和底部注释整体略小，横向占用不足；需要放大以匹配源图的视觉密度。
- 结论区颜色拆分正确，但普通正文略小且片段间距稍松，需要在第二版中重新压紧。
- 卡片边框、橙红/青绿强调色和背景色接近源图，可保持。

## Calibrated PowerPoint render review
- 第二版在真实 PPTX 渲染中，标题宽度、卡片坐标、主流程高度、说明区和底部结构均与源图对齐。
- 标题、眉题、说明句已放大；底部结论的普通文字已放大并压紧，未发生换行或溢出。
- 所有强调色片段仍为独立文本框，箭头、虚线和节点均为独立原生对象。
- 当前差异主要是字体渲染和极细线条的抗锯齿差异，不影响版式与信息表达。

## Side-by-side and blend QA
- 并排图确认六个主卡片的边界、主流程箭头端点、下方分区线和结论起点均与源图处于对应位置。
- 标题横向占用和层级已匹配；真实 PPTX 渲染没有文字换行、卡片穿插或越界。
- 叠加图的主要重影来自源图字体与 PowerPoint 字体渲染差异，图形坐标整体重合。
- 视觉差异统计：mean absolute difference 12.4537/255，阈值 32 的变化像素占比 9.2081%；作为字体重建型页面，结果可接受。
