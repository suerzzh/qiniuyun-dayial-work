# Findings

- 用户要求暖象牙白 `#F5F2EA`、深炭黑 `#20211F`、珊瑚橙红 `#F0442F`、杏橙 `#FF9A70`、少量青绿 `#159A91`、暖灰 `#D9D7D0`。
- 核心证据：146 个记录轮次、33 个会话、113 个可测轮次、首音频中位数约 0.81 秒。
- 证据只能证明端到端 Realtime 路线可行，不能作为生产 SLA。
- 下一阶段：三到十分钟长会话、打断、Redis、移动端、真实用户指标。
- 收束判断：实时对话是底座，教学编排才是产品；Web 先验证，移动端随后扩展；下一里程碑是可靠性与真实用户效果。
- 视觉采用编辑风格的开放画布与细线关系，不采用密集 Dashboard、网页导航或重复卡片阵列。
- GPT Image 2 首次生成即完整呈现全部指定文字与数字，未发现错字、乱码、额外 Logo、页码或无关装饰。
- 源图自然尺寸为 1670×939，已按技能允许的“整图缩放”处理为精确 3840×2160；构图与文字未被裁切或重绘。
- 图片型 PPT 渲染预览与源图构图一致，无裁切、越界或比例失真。
- 背景提取为干净暖象牙白低对比纹理，无文字、线条或残影。
- 框架层完整覆盖左上强调线、上下横分隔线、两组竖分隔线、中心节点以及下一步路径的圆点/箭头；没有普通文字。
- 源页没有独立插画、图标或艺术字，空图标表经绿幕处理后 100% 透明，`slice_grid.py` 正确记录 0 个图标。
- 第一版可编辑预览的主要偏差：标题与数字偏轻偏小；判断句被拆成多个文本框后间距不自然；底部主结论与三条短结论发生换行。
- 第一轮回校：放大标题与核心数字；将判断句改为一个含多色 runs 的富文本框；扩大底部文本框并按原图比例调整字号，保证单行和分栏边界。
- 第二版证明 44pt 标题与 68pt KPI 超过源图窄框承载能力，产生字符级换行；保留富文本与底部修正，同时恢复已经验证能单行的 36pt/58pt。
- 第三版所有文字均保持单行，判断句强调色连续，底部三栏不再换行或压线；与源图的剩余差异主要是可编辑字体字重比 imagegen 位图略轻。
- 最终 blend/diff 检查确认背景与框架锚点基本重合；差异主要集中在 imagegen 位图字体与可编辑系统字体的字宽、字重和基线，不存在缺失文字、重复图标或结构性错位。
